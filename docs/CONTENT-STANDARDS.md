원문 HWP의 선형 텍스트 추출에서는 수식 개체 일부가 빠진다. 범위 판정은 성취기준 문장과 해설을 사용하며, 수식은 각 카드의 가정·검산으로 별도 확인한다. 특정 소단원의 예시가 없다고 교육과정 전체를 다루었다고 설명하지 않는다. 이 서비스의 목적은 단원과 관심사의 연결 글쓰기이며 개념 설명·연습문제의 완전한 대체가 아니다.

## 카드와 질문

- 제목은 생활 장면·궁금증부터. 본문은 쉬운 한국어 3~4문장으로 수학과의 관계를 설명한다.
- 단원당 예시 기본8장 이상, 공통질문 정확히4개, 기본관심사15개별 맞춤질문 정확히1개. 맞춤질문90자 이내.
- 신규 세트는 관심사15개 각각에 자연스러운 예시 최소1장. 본문에 관계가 없는 태그를 붙이지 않고 부족하면 카드를 추가한다. 추가량은 검수 문서에 공개한다.
- 앞3장은 다른 장면·관심사에서 선택. 관심사가 없거나 직접 입력만 있으면 기존 안내와 공통질문 사용.
- 숫자·규칙·자료는 가정임을 밝히고 정의역·단위·모형 범위·불가능한 값 제외·계산을 확인한다. 실제 건강·투자·추천 알고리즘 효과로 일반화하지 않는다.
- 새 카드의 concept는 해당 세트 concepts 목록 중 하나와 정확히 일치한다. ID는 세트 안에서 유일하다. 세트 ID·과목·단원·순서는 기존 목록과 일치한다.

## 그림과 화면

직접 만든 SVG만 사용한다. 기존 팔레트 색과 draw/pop 규칙으로 장면과 수학 내용을 함께 그린다. 모션은 화면 진입 때 한 번, 동작 줄이기·화면 감지 미지원에서는 완성 그림. 스크립트·이벤트·외부 참조·이미지·영상은 넣지 않는다. 모든 그림에 실제 움직임 대상이 있는지 검사하고 그림의 숫자·도형·축 방향이 본문과 맞는지 직접 관찰한다. 개념도는 실제 축척 그림과 구별한다.

학생 흐름은 기존7단계·진행표시·이전·질문 고정·문장틀·자유쓰기·임시복원·공유선택·저장·다시쓰기를 유지한다. 390px에서 긴 수식·질문·그림 글자가 잘리거나 겹치지 않는지 직접 누르고 확인한다. 노트에 16단원이 모두 채워졌을 때도 살펴본다.

## 검증과 교사 검수

`node --test scripts/check-content.test.ts`는 오류 탐지 시험이다. `node scripts/check-content.ts`(또는 `--complete`)는 전체16세트의 구조·개수·관심사·그림 참조와 안전 패턴·모션을 검사한다. XML 문법·시각 배치·수학적 타당성·장면의 자연스러움은 별도 검증이며, 이 명령 통과가 교사 검수나 보안 인증은 아니다. 일부 fixture 폴더만 검사할 때에만 `--dir 경로 --partial`을 명시한다.

새 세트·맞춤 질문은 모두 draft. 예시·그림·공통 질문·개념 등 세트 전체 검수가 완료돼야 status를 reviewed로 바꾼다. 맞춤 질문15개 전체의 검수는 interestPromptsStatus로 따로 기록한다. 일부 검수는 해당 묶음 draft 유지. 내용을 고치면 해당 묶음을 재검수한다. 계획 승인은 교사 콘텐츠 검수·학생 공개·커밋·푸시·배포 승인을 뜻하지 않는다.

학생 자료와 환경파일을 제외한 격리 사본에서 두 DB 환경변수를 비우고 PGlite와 가짜 자료로 시험한다. dorms-check v0.4.0 코드 전용 결과는 비공개로 보관하며, 미확인 운영 DB·공개 응답을 통과로 표시하지 않는다.
