# 다른 수학 과목 확장 구현 계획

> **For agentic workers:** 승인 후 `superpowers:executing-plans` 또는 사용자가 선택한 경우 `superpowers:subagent-driven-development`로 체크 항목을 수행한다. 2026-11-25 사용자가 제작·검증 시작을 승인했다.

**Goal:** 공통수학1의 지침을 신규 4과목·12단원에 적용해 검수 가능한 콘텐츠와 동일한 학생 흐름을 준비한다.

**Architecture:** 기존 `ContentSet`, `CATALOG`, `UnitFlow`, 단원별 저장 구조를 사용한다. 콘텐츠는 JSON, 그림은 기존 지원 방식의 SVG로 작성한다. 공통수학2부터 과목별로 초안 제작·검증·교사 검수를 이어 간다.

**Tech Stack:** 기존 Next.js·React·TypeScript·JSON·SVG·PostgreSQL/PGlite. 새 패키지를 추가하지 않는다.

**Spec:** [확장 설계안](../specs/2026-11-25-subject-expansion-design.md)

## 공통 제약

- 승인 전에는 계획 문서만 변경한다. 커밋·푸시·배포는 별도 요청이 필요하다.
- 미적분 범위는 기존 목록의 미적분I로 제안한다. 미적분II는 제외한다.
- 과목별 단원 ID는 설계안의 12개 기존 값을 그대로 쓴다.
- 단원당 예시 기본 8장·공통 질문 4개·15개 기본 관심사별 질문 1개. 자연스러운 예시 연결이 부족한 관심사는 카드로 보충한다.
- 새 세트와 맞춤 질문은 `draft`. 교사 검수 없이 `reviewed`로 바꾸지 않는다.
- 공통수학1 공개 세트 4개·예시 32장·맞춤 질문 60개 및 초안 17장을 보존한다.
- 실제 학생 자료·운영 DB를 열지 않는다. 시험은 가짜 자료와 격리 PGlite로 진행한다.
- 기존 팔레트·직접 만든 SVG·한 번 재생·동작 줄이기·390px 직접 확인을 적용한다.
- 정책·행동이 달라지는 변경은 `docs/PRD.md`에도 함께 기록한다.

## 검토 초점

1. 두 ‘경우의 수’ 단원의 저장·임시 글·노트·갤러리가 ID별로 분리되는가 → 작업 5.
2. 미검수 세트와 미검수 맞춤 질문이 배포용 실행의 학생 응답에 새지 않는가 → 작업 1·5.
3. 긴 수식·질문과 그림 모션이 휴대폰에서 제대로 보이며 동작 줄이기도 지키는가 → 작업 2~5.
4. 관심사 변경·이전 이동·새로고침·다시 쓰기 때 고른 질문과 작성 내용이 유지되는가 → 작업 5.
5. 16단원에 글이 모두 있을 때 노트의 길 보기 글자가 겹치거나 다음 추천이 잘못되는가 → 작업 5.

## 작업 1. 범위·콘텐츠 기준과 검증 도구

**대상:** `lib/constants.ts`의 `ContentSet`·`INTERESTS`, `lib/content.ts`의 `CATALOG`, `docs/PRD.md`, 신규 `scripts/check-content.ts`, 신규 `docs/CONTENT-STANDARDS.md`.

**인터페이스:** 기존 `ContentSet` 형식을 유지한다. `node scripts/check-content.ts`는 전체 `content/sets/*.json`을 검사하며 오류 시 종료 코드 1, 성공 시 0을 반환한다. 기존 콘텐츠는 ID·기본 구조·SVG 유효성·검수 상태의 회귀 기준으로 검사하고, 신규 12세트에 추가 완성 기준을 적용한다.

- [ ] 공식 교육과정 원문에서 12단원의 소단원·성취기준·범위를 확인하고 출처·확인일을 기준 문서에 기록한다. 특히 미적분I의 함수 범위와 두 ‘경우의 수’의 차이를 명시한다.
- [ ] 기준 문서에 생활 장면 문구, 계산 조건, 질문 90자 이내, 관심사 15개 연결표, 직접 제작 그림·모션·교사 검수 기준을 정리한다.
- [ ] 격리된 가짜 JSON으로 잘못된 단원 ID·과목/단원 불일치·예시 ID 중복·필수 필드 누락·관심사 오타·질문 부족·안전하지 않은 SVG를 검사 도구가 거부하는 사례를 먼저 만든다. 같은 그림을 재사용하는 경우는 허용하되 SVG 참조는 존재해야 한다.
- [ ] 검사 도구를 구현해 위 실패 사례와 기존 공개 4세트의 정상 통과를 확인한다. 신규 세트는 예시 최소 8장, 질문 4개/15개, 관심사 15개 예시 연결, 유효한 그림과 움직임 대상, 단원별 개념 연결을 검사한다. 수학과 장면의 자연스러움은 사람의 검토로 남긴다.
- [ ] PRD G1·G2·G3와 일정에 확장 범위·추가 카드 허용·세트/맞춤 질문 별도 검수·전체 신규 그림의 동일 기준을 반영한다. ‘공개 32개’라는 현재 사실과 ‘모든 신규 그림’이라는 제작 기준을 구별한다.

**검증:** `node scripts/check-content.ts`의 정상·오류 시험, 기존 4세트 파일 해시·개수 비교. 실패 fixture는 임시 폴더를 사용하며 실제 콘텐츠를 고쳐 시험하지 않는다.

## 작업 2. 공통수학2 3세트 — 첫 단원에서 기준 확인

**생성:** `content/sets/cm2-figures.json`, `cm2-sets.json`, `cm2-functions.json`, `docs/CONTENT-REVIEW-CM2.md`.

**인터페이스:** 기존 `ContentSet` JSON, 두 검수 상태 모두 `draft`. 새 SVG는 우선 각 카드의 `svg`에 직접 넣고 `illus: null`을 사용한다. 반복되는 도식 조각이 실제로 필요할 때만 `lib/illus.ts`의 기존 방식을 확장한다.

- [ ] 먼저 `cm2-figures` 한 세트의 개념·예시 8장 이상·질문 4개/15개와 그림을 작성한다. 앞 3장은 서로 다른 장면으로 배치한다.
- [ ] 계산·가정·교육과정 범위·본문과 태그의 연결·그림 대응·모션을 검토하고 검사 도구를 통과시킨다. 검수 문서에 원문·수식·검산·출처·그림 설명·카드별 승인 칸·질문 승인 칸을 기록한다.
- [ ] 같은 기준으로 `cm2-sets`, `cm2-functions`를 제작한다. 연결표 3×15칸에 예시 ID와 맞춤 질문을 대응한다.
- [ ] 격리 개발 환경과 390px 브라우저에서 세 단원의 모든 카드·질문, 긴 수식·모션·동작 줄이기를 확인한다.
- [ ] 선생님에게 과목별 검수 자료를 제시한다. 답변이 없으면 초안을 유지한 채 다음 과목의 초안 제작으로 진행할 수 있다.

**검증:** 3세트·기본 예시 24장 이상·공통 질문 12개·맞춤 질문 45개, 세트/질문 `draft`, 45개 관심사 연결, 검산과 전 카드 그림 관찰.

## 작업 5. 전체 사용 흐름·공개 차단·보안 검증

**검토/필요 시 최소 수정:** `lib/content.ts`, `lib/views.ts`, `lib/recommend.ts`, `app/u/[unitId]/page.tsx`, `app/u/[unitId]/UnitFlow.tsx`, `app/u/[unitId]/gallery/`, `app/notes/Notes.tsx`, `app/admin/Stats.tsx`, `components/Illus.tsx`, `app/globals.css`. 근거 없이 이 파일들을 모두 바꾸지 않는다.

- [ ] 환경파일·기존 `.data/` 없는 격리 사본에서 `DATABASE_URL`과 `POSTGRES_URL`을 모두 비운다. 서버의 첫 쿼리 전에 `usingLocalDb()`가 true인지 확인하고 새 PGlite에 가짜 자료만 넣는다. 앞선 과목별 화면 시험에도 같은 조건을 적용한다.
- [ ] 가짜 계정의 PGlite 시험에서 신규 12단원 각각 처음 쓰기 → 저장 → 노트 → 다시 쓰기를 확인한다. 두 ‘경우의 수’에 다른 글을 넣어 임시 글·DB·노트·갤러리가 구분되는지 확인한다.
- [ ] 네 과목 대표 단원에서 관심사 변경, 이전 이동, 선택 질문 유지, 작성 방식 변경, 새로고침 복원, 공유 끄기, 처음/다시 쓰기 구분을 직접 확인한다. 다른 단원·다른 계정의 임시 글이 섞이지 않는지도 확인한다.
- [ ] 가짜 두 계정으로 단원 글 저장 전 갤러리 거부, 저장 후 해당 단원만 열람, 공유 끈 글 비노출을 확인한다.
- [ ] 임시 소스 사본에서 `draft/draft`, `reviewed/draft`, `reviewed/reviewed`를 각각 시험한다. `NODE_ENV=production`, `SHOW_DRAFT_SETS` 미설정 상태에서 홈·직접 주소·서버 저장·갤러리·학생 전달 데이터의 공개 범위가 맞는지 확인한다. 실제 교사 승인 전 원본 파일은 `draft`로 유지한다.
- [ ] 열린 단원·미완료 단원·과목 경계·모두 작성한 상태에서 다음 추천을 확인한다. 연습 계정이 16단원을 모두 쓴 상태로 390px 노트의 길·판 보기와 운영자 단원 합계의 과목 구분을 확인한다. 겹침이 재현되면 기존 디자인 안에서 최소 수정하고 재확인한다.
- [ ] `npx tsc --noEmit`, `node lib/totp.ts`, `node lib/recommend.ts`, `node scripts/check-content.ts`, `npm run build -- --webpack`를 실행하고 결과를 기록한다. 환경 제약으로 실패한 것은 통과로 처리하지 않는다.
- [ ] 민감 자료 없는 소스 사본에서 고정 v0.4.0의 `detect` → `scan --code-only --track security` → `status` → `report`를 실행해 항목별 근거를 읽는다. 기존 설정을 재사용하고 보안 보고서는 공개 변경에서 제외한다. 환경파일 Git 추적과 새 SVG의 외부 참조·실행 코드를 별도 확인한다.
- [ ] 공통수학1 원본 보존, 새 세트·질문 개수와 상태, 추가 예시 수, 실제 390px 조작, 미확인 항목을 최종 기록한다. 브라우저 불가 시 해당 체크는 미완료로 남긴다.

## 작업 6. 교사 검수 반영과 공개 준비

**대상:** 검수 받은 `content/sets/*.json`, 과목별 검수 문서, `docs/CONTENT-REVIEW.md`, `docs/PRD.md`, `README.md`, `tasks/todo.md`.

- [ ] 예시·그림·공통 질문·개념 등 세트 구성 전체의 교사 검수 완료 답변을 받은 세트만 `status: reviewed`로 바꾼다. 맞춤 질문 15개 전체의 검수 완료 답변을 받은 묶음만 `interestPromptsStatus: reviewed`로 바꾼다. 검수 날짜·범위를 기록하고, 일부만 승인되거나 수정이 필요하면 해당 묶음 전체를 `draft`로 유지해 보완·재검수한다.

- [ ] 결과와 남은 미확인을 보고한다. 커밋·푸시·배포 요청이 오기 전에는 이 단계에서 멈춘다.
