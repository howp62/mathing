# 다른 수학 과목 확장 설계안

2026-11-25 · **사용자 계획 승인 완료** · 콘텐츠 제작·비공개 검증 진행 중

## 목적과 범위

공통수학1에서 정한 콘텐츠·글쓰기·그림·접근성·개인정보 지침을 공통수학2, 대수, 미적분I, 확률과 통계에도 적용한다. 처음 사용하는 고등학생이 휴대폰으로 단원을 골라 관심사와 수학을 연결하는 글을 쓰고, 저장한 뒤 다른 학생의 글을 읽고 다시 쓰게 한다.

사용자의 ‘미적분’은 기존 `docs/PRD.md:52`와 `lib/content.ts`의 **미적분I**로 해석한 제안이다. 미적분II는 이번 범위에 포함하지 않는다. 기존 과목·단원 ID를 유지하며, 이미 공개된 공통수학1 4세트와 검수 대기 보강 초안 17장은 보존한다.

| 순서 | 과목 | 기존 단원 ID와 단원 | 기본 제작량 |
|---|---|---|---|
| 1 | 공통수학2 | `cm2-figures` 도형의 방정식 / `cm2-sets` 집합과 명제 / `cm2-functions` 함수와 그래프 | 예시 24장·공통 질문 12개·맞춤 질문 45개 |
| 2 | 대수 | `al-explog` 지수함수와 로그함수 / `al-trig` 삼각함수 / `al-sequences` 수열 | 예시 24장·공통 질문 12개·맞춤 질문 45개 |
| 3 | 미적분I | `c1-limits` 함수의 극한과 연속 / `c1-derivatives` 미분 / `c1-integrals` 적분 | 예시 24장·공통 질문 12개·맞춤 질문 45개 |
| 4 | 확률과 통계 | `ps-counting` 경우의 수 / `ps-probability` 확률 / `ps-statistics` 통계 | 예시 24장·공통 질문 12개·맞춤 질문 45개 |

합계: **12세트, 예시 최소 96장과 각 그림, 공통 질문 48개, 맞춤 질문 180개**, 단원별 소단원·개념 목록 및 교사 검수 자료. 기존 4세트와 합쳐 총 16세트가 된다.

## 현재 확인한 구조

- `content/sets/`에는 공통수학1 JSON 4개만 있다. 각 세트는 예시 8장, 공통 질문 4개, 기본 관심사 15개별 질문을 갖는다.
- `lib/content.ts`에는 전체 16개 단원이 이미 등록돼 있다. 콘텐츠 파일을 추가하면 기존 홈·단원·노트·운영자 화면에서 같은 ID를 사용한다.
- `UnitFlow`는 과목 전용 화면이 아닌 공통 흐름이다. 도입은 예시 앞 3장, 관심사 예시는 맞는 카드 최대 3장, 맞춤 질문은 선택한 관심사 중 최대 3개를 사용한다.
- `lib/views.ts`의 `isOpen`과 `openSet`, 단원 페이지는 세트와 맞춤 질문의 검수 상태를 각각 확인한다. 개발 모드 또는 `SHOW_DRAFT_SETS=1`에서는 초안도 보이므로 비공개 시험 환경과 운영 환경을 구분해야 한다.
- 글은 `unit_id`로 구분되고 `(user_id, unit_id)`가 유일하다. 현재 조사 범위에서는 DB 구조 변경이 필요하지 않다.
- 공통수학1 보강 초안 17장은 아직 별도 검수 대기다. 새 과목 확장이 그 초안의 검수 완료나 공개를 뜻하지 않는다.

## 적용 방식과 대안

**제안: 기존 공통 흐름 + 과목별 콘텐츠 추가 + 순차 검수.** 이미 여러 과목을 처리하는 화면과 저장 구조가 있으므로 콘텐츠 품질과 실제 학생 흐름에 작업을 집중한다.

- 과목별 화면 복제: 같은 개선을 여러 번 반영해야 하므로 채택하지 않는다.
- 새 콘텐츠 관리 시스템·DB 모델 도입: 현재 12세트 추가에 필요하지 않아 이번 범위에서 제외한다.
- 네 과목 일괄 제작·일괄 검수: 마지막에 오류와 교사 검수량이 몰린다. 대신 공통수학2 한 단원으로 기준을 확인한 후 과목별로 제작·검수한다. 한 과목의 검수를 기다리는 동안 다음 과목의 초안은 준비할 수 있다.

## 모든 과목에 적용할 기준

1. **장면부터 설명:** 제목은 학생이 겪을 장면이나 궁금증으로 시작한다. 본문 3~4문장에서 해당 단원의 수학과 연결하며, 전문 용어만 나열하거나 억지로 진로와 연결하지 않는다.
2. **수학 검증:** 공식 교육과정 원문의 성취기준으로 단원·개념 범위를 확인한다. 숫자는 가정임을 밝히고 정의역·단위·계산·적용 조건·불가능한 값 제외를 검산한다. 사실 설명이 필요하면 신뢰할 수 있는 원출처와 확인일을 교사 검수 문서에 남긴다. 수학 모형을 실제 건강·투자 효과로 단정하지 않는다.
3. **관심사 누락 방지:** 단원마다 기존 기본 관심사 15개 각각에 질문 1개와 자연스럽게 연결되는 예시 최소 1장이 있는지 표로 확인한다. 한 카드의 여러 태그는 본문이 각 관심사와 실제로 연결될 때만 허용한다. 8장으로 부족하면 예시를 추가한다. 이는 PRD G1의 ‘8장’을 ‘기본 8장, 관심사 보강 시 추가’로 고치는 제안이며, 추가량은 과목별 검수 문서에 기록한다. 직접 입력한 관심사는 기존 공통 질문과 안내를 사용한다.
4. **다양한 도입:** 각 세트 앞 3장은 서로 다른 장면·관심사를 선택한다. 같은 장면에 숫자와 과목 이름만 바꾼 예시를 반복하지 않는다.
5. **질문:** 공통 질문 4개와 관심사별 질문 15개를 준비한다. 답이 하나로 정해진 계산 문제보다 자기 경험과 연결할 여지를 준다. 맞춤 질문은 기존 검수 기준인 90자 이내로 작성한다.
6. **그림과 움직임:** 모든 예시에 직접 만든 ‘장면 + 수학’ SVG를 넣는다. 기존 팔레트·`Illus`·`draw`/`pop` 방식을 사용한다. 화면 진입 때 수학 부분이 한 번 나타나고, 동작 줄이기·감지 미지원에서는 완성 그림이 보인다. 외부·AI 이미지·영상은 추가하지 않는다. 그림 수와 별개로 실제 움직임 대상을 전부 확인한다.
7. **쓰는 흐름:** 7단계 표시, 이전 이동, 현재 질문 펼침·고정, 질문을 바꾸어도 글 유지, 3단계/자유 쓰기, 문장 틀, 임시 보관, 저장 피드백을 그대로 적용한다. 계정·단원·처음/다시 쓰기 임시 글을 분리한다.
8. **구분과 접근성:** 내 글/다른 학생 글, 처음/다시 쓴 연결은 색과 이름으로 구분한다. 버튼은 행동을 나타내는 쉬운 말로 쓴다. 390px에서 긴 질문·수식·그림의 글자가 잘리거나 겹치지 않고, 쓰는 칸과 주요 버튼을 직접 조작할 수 있어야 한다.
9. **같은 이름의 단원:** 공통수학1과 확률과 통계의 ‘경우의 수’는 기존 서로 다른 ID를 유지한다. 새 세트는 공식 범위에 맞는 심화 내용을 담고, 노트·저장·추천·갤러리가 섞이지 않는지 확인한다.
10. **검수 후 공개:** 새 세트와 맞춤 질문은 모두 `draft`로 시작한다. AI의 계산·구조·문구 검토는 교사 검수를 대신하지 않는다. 예시·그림·공통 질문·개념 등 세트 구성 전체의 교사 검수가 끝나야 `status: reviewed`로 바꾼다. 맞춤 질문 15개 전체의 교사 검수가 끝나야 `interestPromptsStatus: reviewed`로 바꾼다. 카드나 질문 일부만 검수가 끝나면 해당 묶음 전체는 `draft`로 유지한다. 바뀐 내용은 해당 묶음을 재검수한다.

## 안전과 변경 경계

- 개인정보 수집 항목, 인증·인가, 공유 기본값, API, 의존성, DB 구조는 이번 확장에서 바꾸지 않는다. 학생 글을 예시 자료로 사용하지 않는다.
- 기존 공통 화면은 재사용한다. 확장으로 드러난 배치·과목 혼동 문제만 재현 근거와 함께 최소 수정한다. 전체 첫 화면 재설계나 과목별 새 소개 영상은 만들지 않는다.
- 새 그림은 저장소의 신뢰한 SVG와 기존 안전 검사를 사용한다. 외부 참조·이벤트·스크립트를 넣지 않는다.
- 구현 시 dorms-check **v0.4.0**을 적용한다. 실제 학생 자료·환경파일·기존 보안 보고서를 제외한 소스 사본에서 코드 전용 검사하고, 결과는 비공개로 보관한다. 운영 DB·익명 DB 읽기 프로브는 실행하지 않는다.
- 2026-11-25 계획을 승인받아 콘텐츠 제작·비공개 검증을 진행한다. 커밋·푸시·배포는 별도 요청 전 하지 않는다. `reviewed` 표시와 운영 공개 역시 별도 범위로 다룬다.

## 승인 후 완료 기준

- 12세트가 위 제작량과 15개 관심사 연결표를 만족하고, 계산·가정·교육과정 근거·SVG·식별자 검사를 통과한다.
- 공통수학1의 기존 공개 4세트·32장·질문 60개와 별도 초안 17장이 보존된다.
- 환경파일·기존 `.data/`가 없는 격리 사본에서 `DATABASE_URL`과 `POSTGRES_URL`을 모두 비우고, 쿼리 전 `usingLocalDb()`가 true인지 확인한다. 가짜 계정과 새 PGlite로 12단원 각각 쓰기 → 저장 → 노트 → 다시 쓰기를 확인한다. 단원별 갤러리 열람 조건과 다른 단원 글 분리도 확인한다.
- 배포용 실행에서 `SHOW_DRAFT_SETS`를 비운 상태로 미검수 세트는 홈·직접 주소·저장·갤러리에서 열리지 않고, 미검수 맞춤 질문은 학생 전달 데이터에도 포함되지 않는다. 실제 승인 전에는 검수 상태 조합을 임시 사본으로만 시험한다.
- `npx tsc --noEmit`, `node lib/totp.ts`, `node lib/recommend.ts`, 콘텐츠 검사, 배포용 빌드가 통과한다.
- 390px 실제 브라우저에서 12단원의 카드·질문을 살펴보고 네 과목의 대표 흐름을 직접 누른다. 전체 예시 그림은 검수용 모음에서도 모두 관찰한다. 완성 글이 16단원 모두 있는 연습 계정으로 노트의 길·판 보기에서 겹침도 확인한다.
- 브라우저 접속 등으로 확인하지 못한 항목은 미완료로 남기고 완료를 주장하지 않는다. 확인한 위험·권고·미확인은 구분해 보고한다.

## 승인 요청의 의미

이 설계와 연결된 구현 계획에 대한 승인은 **12단원 콘텐츠·그림·검수 자료 제작, 비공개 시험, 필요한 최소 공통 수정**을 시작하는 데 대한 승인이다. 각 세트의 교사 검수 완료, 학생 공개, 커밋·푸시·배포 승인을 대신하지 않는다.
